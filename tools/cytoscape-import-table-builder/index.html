Key comparison

Keys are shown as quoted text so boundary spaces remain visible. Data rows are 1-based, excluding headers and truly blank physical lines. Long row/key lists are abbreviated here; JSON retains all groups and CSV retains every parsed data row.

Inspect keys, not biological identity

No fuzzy matching, alias conversion, species mapping, automatic trimming, deduplication, or joined/cleaned annotation export is performed. Duplicate network keys may be intentional, but they are not one-to-one identifiers. Conflicting duplicate annotations require review.

A high overlap is not an import guarantee. In Cytoscape, confirm the actual target network, both key columns, and their data types. This browser checker does not inspect an open Cytoscape session. Cytoscape table import instructions.

Limits: 25,000 data rows and 200 columns per table; 10 million decoded characters per input; 1,000 characters per key. No uploads, analytics, or automatic storage. Reports contain original identifiers; keep them private. SHA-256 fingerprints track decoded input text, not original file bytes or authorship.

What this tool does—and does not do

It matches the workflow’s default sizes (42 px; 56 px for core genes), label sizes (10/12 px), and borders (0.8/2.0 px). Missing modules become “Unclassified”; missing colors become gray. The node CSV is authoritative when individual genes have color overrides; the lookup can contain more than one color per module.

It does not infer modules, check biological evidence, build edges, create a Cytoscape network, or generate the workflow’s provenance files. For the complete evidence and heatmap pipeline, see Functional Module Evidence Mapping.
